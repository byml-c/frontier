# Agent 驱动论文研究系统：首版需求文档

## 1. 产品目标

构建一个面向个人研究者的 Agent 驱动论文研究系统，持续跟踪具身智能领域的新论文，并围绕“研究问题”维护长期演化的研究方向图谱。

首版的核心价值不是罗列论文，而是回答：

1. 新论文与已有研究方向有什么关系；
2. 新论文解决了什么问题、带来了什么增量；
3. 哪些论文值得进入精读；
4. 哪些进展值得更新已有节点或形成新的交叉方向。

首版以响应式 Web 为用户入口，以 Codex Agent 为流程调度与内容判断主体，以 Toolkit CLI 和 Server 为稳定的数据与工具层。

## 2. 用户与使用场景

- 单用户个人系统，不建设多用户、角色或账号体系。
- 部署于具有公网 IP 的阿里云服务器。
- 应用自身不提供账号登录；通过受信设备访问，推荐使用 Tailscale 管理手机、电脑和服务器的设备信任。
- 手机和电脑切换网络或网段后仍可访问。
- 移动端主要用于浏览日报、阅读 PDF、划词翻译、记录笔记和与 Agent 精读对话。
- 桌面端主要用于查看、整理研究图谱，管理论文、日报、记忆和任务。

## 3. 首版范围

### 3.1 包含

- arXiv 自动采集；
- 手动提交普通论文 URL、arXiv ID/链接和 PDF；
- 论文元数据、PDF、分析、阅读记录和状态的持久化；
- 每日筛选、全文分析、推荐和网页日报；
- 响应式 PDF 阅读、翻译、高亮、笔记和带原文引用的 Agent 对话；
- 完成精读后的反馈、标签和优质论文确认；
- 问题驱动的研究方向有向图及增量进展维护；
- Agent 个人兴趣画像、经验记忆和独立记忆页面；
- 给 Agent 使用的 Skill 与非交互式 Toolkit CLI；
- 任务状态、失败原因、日志、手动运行和本地 Git 日备份。

### 3.2 暂不包含

- 邮件、飞书、微信推送；
- 公众号、会议网站等额外自动数据源；
- Zotero 实际同步；
- 多用户及账号登录；
- 复杂边类型、边权或单独的概念知识图谱；
- 复杂的事件溯源和逐操作回滚；
- 完整替代 Zotero 的文献管理能力；
- 多模型路由。

## 4. 系统边界与架构职责

### 4.1 Agent

- 通过 Skill 获得工作流程、判断标准和成功条件；
- 负责采集策略、论文理解、筛选推荐、全文分析、图谱更新、记忆更新和对话；
- 只能通过 Toolkit CLI 操作 Server 数据，不直接访问数据库或服务端数据文件；
- 每次任务可以独立启动，不预设持有历史上下文；
- 可以显式检索和更新 Server 中的经验记忆与个人画像。

### 4.2 Toolkit CLI

- 提供供 Agent 调用的非交互式原子命令；
- 输入、输出使用稳定 JSON；
- 不包含模型推理或推荐判断；
- 负责参数校验、调用 Server、返回结构化结果以及可安全重试。

### 4.3 Server

- 提供 API、任务调度、持久化、文件存储、PDF 解析、日志和备份；
- 执行数据约束、去重、幂等和基础一致性校验；
- 每天北京时间 09:05 触发日报 Agent，启动时间可按分钟调整；
- 任务失败时保留上一期日报，记录并展示失败原因，不无限自动重试。

### 4.4 Web

- 只负责用户交互和数据呈现；
- 桌面端提供可收起的全局 Agent 侧边栏；
- 移动端将全局 Agent 对话显示为弹出式全屏窗口；
- Agent 对话自动携带当前页面、论文或节点上下文。

## 5. 数据来源与初始化

### 5.1 arXiv 自动采集

- Agent 根据研究图谱和兴趣画像自动维护检索策略，不要求用户维护固定关键词。
- 初始关注范围来自 `start.md`：VLA、WAM、移动操作、触觉、仿真、评测、遥操以及 3DV 的具身应用。
- 检索应保留一定广度，使 Agent 有机会发现尚未进入图谱的新热点。

### 5.2 手动提交

- 支持普通论文 URL；
- 支持 arXiv ID 或链接；
- 支持直接上传 PDF；
- 已存在的论文跳转到原记录并提示重复，不新建重复条目。
- Web 手动添加的论文立即进入当天简报的“手动添加”推荐区，不受日报总量和重点推荐篇数限制，也不占用自动推荐额度；
- Server 为其创建独立全文分析任务，处理期间显示“处理中”和内容占位，完成后展示作者信息、简介、评语、问题、创新、实验、局限和推荐理由；失败时保留论文并展示具体原因。

### 5.3 初始化

- 从 `我的文库.bib` 的 151 条记录中自动筛选与关注领域相关的论文；
- 导入相关论文已有的个人笔记；
- 忽略课程作业等无关主题；
- 允许在文库之外补充少量近五年内的领域奠基性工作；
- 目标是形成规模较小、关系可靠的初始核心图，不追求完整学术史；
- 开发测试使用最近一周的 arXiv 论文验证推荐流程。

### 5.4 去重与版本

- 通过 arXiv ID、DOI 和规范化标题合并重复论文；
- 保存 arXiv 版本历史；
- 新版本默认不重复推荐；
- 对已精读或已关注论文，只有方法、实验或结论发生显著变化时才重新进入候选，并标记为版本更新。

## 6. 每日采集与推荐流程

### 6.1 处理漏斗

1. 按 arXiv 大分类和提交日期分页召回，默认窗口为 3 天、扫描最新 300 条；服务端用高召回的通用视觉、机器人、具身和 Agent 词族做预筛，最多把 120 条交给 Agent，不附加 VLA/WAM 等细分关键词；
2. Agent 根据预筛后的标题、摘要和作者做最终语义领域筛选：默认大领域为 3D 视觉、具身智能、AI Agent；AI Agent 包含工具使用、规划、多 Agent、记忆和计算机操作；
3. 交给 Agent 前按无版本 arXiv ID、规范化 DOI、标题排除库中全部已存在论文（含 candidate）及批内重复；新文章领域不符则不入库，符合则入库；
4. 根据用户兴趣收敛到约 100 篇候选（通常 80–120），保留约 15% 的领域内探索空间。`abstract_limit` 表示此阶段目标，不限制原始摘要浏览量；
5. 保存候选池，按质量和相关度分别评分，从池中选出 20–50 篇日报；
6. 全部入选文章翻译摘要、生成简评；其中排名最前的最多 10 篇阅读全文、生成完整分析并预处理。

入选的 20–50 篇还要由 Agent 核对第一作者、第一单位和通讯作者，并用简体中文总结单位及核心课题组完成的研究方向；自动解析值仅作线索，用户手动修订优先。保存 `research_group_summary` 和 `metadata_json.agent_bibliography` 的置信度、证据说明，卡片用 MUI 展开图标显示总结。

使用 `source arxiv-discover` 一次获取预筛结果；服务端在该请求内完成上游分页和粗筛，不让 Agent 继续翻页补足数量。`scan_capped` 和 `prefilter_capped` 表示不同阶段截断，候选不足须说明原因。最终领域判断和兴趣选择由 Agent 执行；后端验证候选池论文存在、未读、无重复、最多为目标的 120%，并校验日报入选范围。

阈值和领域可在 Web 设置页面调整。细分兴趣 `initial_interest_domains` 仅影响兴趣排序；作者影响力不绕过领域筛选。用户手动添加的文章不占自动推荐名额。

### 6.2 时间衰减

- 新召回限定配置的 UTC 提交日期窗口，并扫描最新 `discovery_scan_limit` 条；已入库候选不按自然日清空；
- 已入库候选仍可在论文库手动阅读，但每日新发现阶段不会重复把它们交给 Agent；
- Agent 在排序时综合研究价值、个人相关性和新近程度，目前不使用固定时间衰减公式。

### 6.3 全文分析

- 仅对最终排名前 `min(fulltext_limit, featured_limit, 10)` 篇读取完整 PDF，其他文章先做摘要级评估；
- 默认以可提取正文文本为主；
- 当架构图、表格或曲线承载关键证据时，Agent 可按需请求并读取对应图表；
- 关键分析结论应能定位到 PDF 页码、章节或原文片段。

### 6.4 推荐反馈闭环

- “研究价值”和“个人相关性”是两个独立信号；
- Agent 分数为 0–1 连续预测且不可由用户编辑；用户质量和兴趣均使用五档评价（质量：很差、较差、一般、较好、优秀；兴趣：不相关、较不相关、一般、较相关、高度相关）；用户可点击 Agent 分数表示已看摘要并认可该判断；
- 日报中的点击精读是强正向兴趣信号；
- 忽略时必须填写原因，Agent 据此判断是仅忽略单篇还是调整兴趣画像；
- 精读完成后的标签与用户确认结果进一步更新推荐策略；
- Agent 可以从精读对话中推断用户态度，但必须先由用户确认。

## 7. 每日简报

### 7.1 页面结构

1. 顶部全局导航；
2. 少于 5 篇的“今日重点推荐”；
3. 其余论文按 Agent 判断的潜在相关方向分组，但不因此写入研究图谱；
4. 同一论文只显示一张主卡片，可展示多个潜在相关方向；
5. 独立的“潜在新方向”区域；
6. 进入完整图谱的快捷入口。

### 7.2 论文卡片

默认展示：

- 标题；
- 一作；
- 原文可靠标注时展示通讯作者，否则显示“未标注”；
- 第一作者的第一单位，无法确认时显示“待确认”；
- 来源和日期；
- 一句话简介；
- Agent 一句话评语。

展开后展示：

- 解决的问题；
- 创新内容；
- 实验效果；
- 遗留问题；
- 关联研究方向节点及关联理由。

卡片底部：

- 左侧提供“精读”和“忽略”；
- 忽略必须填写原因；
- 右侧提供原文链接；
- “感兴趣、优质论文、创建节点”等操作在完成精读后出现。
- 简报卡片提供统一“论文信息”入口，可查看和编辑当前论文 metadata。

### 7.3 日报归档

- 日报发布后作为不可手动修改的快照长期保存；
- 首页展示最新一期；
- 独立页面按日期浏览历史日报；
- 推荐内容保持发布时状态，论文当前阅读状态可以动态更新。

## 8. PDF 阅读与精读

### 8.1 双视图

- PDF 阅读视图和 Agent 对话视图可以切换；
- 桌面端允许宽屏组合；
- 移动端优先保证阅读体验；
- 两端同步并恢复阅读页码和进度。

### 8.2 PDF 基础能力

- 目录和页码跳转；
- 缩放；
- 文本搜索；
- 常规触控和滚动阅读；
- 建议基于 PDF.js 实现。

### 8.3 阅读标注

- 划词或划句翻译；
- 翻译使用流式响应；同一论文、页码和归一化文本的结果长期缓存，缩放或重新划选后仍可直接命中；
- 单词翻译同时给出基础释义和当前论文语境中的释义；
- 简单翻译使用模型的非思考模式；单词上下文直接取自当前页面文本层，不允许在首个流事件前同步抽取整篇 PDF；
- 高亮即创建一条可为空的笔记，高亮位置、颜色和笔记内容长期保存；
- 用户可在笔记面板调整高亮颜色、编辑内容，删除笔记时同时删除高亮；
- 添加个人笔记并长期保存；
- 右侧“笔记”页签集中展示笔记，支持点击跳转到原文位置和编辑；
- 将一段或多段选中文本添加到聊天草稿，并可在发送前逐条移除；
- 翻译不写入 Agent 对话；
- 发送问题时保存全部引用原文、页码和位置，并进入论文精读对话。

### 8.4 精读对话

- 每篇论文拥有独立且可恢复的对话；
- Agent 回答使用流式响应，正文生成时持续呈现；
- 正文生成前展示可公开的分析摘要、工具调用开始/结束状态和简短结果，使用户能判断 Agent 是否仍在工作；不展示隐藏推理或敏感工具参数；
- Agent 回答中的关键结论必须附带可点击的原文依据；
- 点击引用后 PDF 跳转并高亮对应位置；
- 对话以问题分解和互问为主，不按论文目录机械复述；
- 常用结构为“问题 → 方法/证据 → 结论 → 新问题”；
- 对话中产生的子问题默认不进入图谱。
- 全局 Agent 与论文精读对话统一渲染 Markdown、GFM 表格/列表、代码块和 LaTeX 行内及块级公式；论文页码引用仍可点击跳转。

### 8.5 完成精读

- 精读结束只由用户主动点击；
- Agent 汇总 PDF、高亮、笔记和对话，形成结构化精读结论；
- Agent 生成的用户态度和标签建议必须由用户确认；
- 用户分别确认五态质量与五态兴趣，并选择是否值得创建新节点；
- 每日分析与精读结论统一使用“解决的问题、创新内容、实验结果、局限、未解决问题、用户态度”；每日分析不推断用户态度；
- 标签弹窗展示全部已有标签并突出 AI 推荐标签；
- 标签的新建和最终选择完全由用户完成。

## 9. 论文库与积累库

- 数据库保存所有候选、忽略、推荐、精读中和已精读论文及相关记录；
- “论文库”展示数据库中的全部论文，手动添加和日报采集成功后立即可见；
- “积累库”展示已完成精读并由用户确认反馈的论文，标签和所属研究节点在卡片中直接可见；
- 论文库卡片突出显示阅读状态和日期，标签使用以间隔符分隔的彩色文字链接；
- 两个视图共用标题/作者搜索，并提供状态、优质、兴趣和标签等简单筛选；
- “优质论文”是积累库中的进一步筛选，不是进入积累库的前提；
- 简报、论文库和精读页共用同一个论文信息窗口，可编辑标题、作者、一作、通讯作者、第一单位、来源、日期、链接、摘要、Agent 分析、评分、标签和扩展 metadata；
- 论文信息窗口的“分析与标签”支持用户手动要求 Agent 重新阅读全文并生成分析；未保存的人工修改存在时禁止触发，避免覆盖编辑；
- 标签编辑使用可搜索的已有标签下拉列表；输入内容没有匹配项时才显示“新建标签”；
- Zotero 联动不在首版实现，只预留单向同步接口；
- 未来只需从本系统向 Zotero 同步精读论文库、PDF、高亮和笔记。

## 10. 研究方向图谱

### 10.1 节点和边

- 节点由一个核心关注问题定义，不是固定学科标签；
- 同一节点可以关联多篇提出、定义或解决该问题的论文；
- 一个节点可以有多个父节点，例如 `VLA → 引入触觉提升精细操作能力 ← 触觉`；
- 首版使用无类型有向边，暂不引入边类型和边权；
- 当问题引出新的具体问题，或节点论文过多时，Agent 可以自动创建更具体的后续节点；
- Agent 可直接修改图谱，用户通过全局 Agent 对话纠正。
- 候选论文和日报论文只记录潜在关联；只有用户完成精读并确认反馈后，Server 才允许建立正式的论文—节点连接和论文驱动的节点进展。

### 10.2 节点详情

节点详情分区或使用 Tab：

- 概览：核心问题、研究内容、已解决问题、待解决问题和关键论文；
- 论文：节点关联的全部论文；
- 进展：按时间排列的增量进展记录；
- 关系：父节点、子节点和关联路径；
- 想法：用户明确要求 Agent 保存的研究 idea。

每篇已确认完成精读的论文正式连入节点时，Agent 增量更新节点概览和进展，不周期性重写整个节点。

### 10.3 想法列表

- 对话中的普通子问题不自动写入；
- 只有用户显式要求时才保存；
- 每条包含内容、来源论文或对话、创建时间和备注；
- 支持待探索、已有论文支持、已解决、放弃等状态；
- 想法可以在以后转成正式节点。

### 10.4 知识链接

- 不建立独立的细粒度概念图谱；
- 优先建立同节点论文间的知识链接；
- 其次检查相邻父子节点；
- 局部连接不足时，Agent 探索已有图谱中的跨领域联系，并可能形成交叉问题节点。
- 上述连接只在论文完成用户确认的精读后建立；日报推荐本身不构成图谱连接。

### 10.5 图谱交互

- 使用 Force Graph 呈现；
- 默认聚焦当前关注节点周围的局部子图；
- 沿节点方向探索时增量加载后续或相邻节点；
- 提供搜索、领域筛选、展开邻居和查看全图；
- 节点位置应稳定并缓存；
- 新节点只触发局部布局调整；
- 聚焦完成后降低或停止模拟，避免节点持续晃动；
- 桌面端支持拖动、缩放和整理；
- 缩放图谱时节点文字保持固定屏幕字号，不随节点缩放，也不得发生单轴挤压；
- 移动端以搜索、节点列表和局部子图为主；
- 移动端竖屏时图谱占满可用视口，未选择节点时不保留空白详情区；
- 整体视觉简约、克制，默认采用 Material UI 的蓝色亮色主题。

## 11. 记忆

### 11.1 分类

- 论文事实、精读结果和领域进展进入论文库和图谱；
- 用户兴趣与评价习惯进入个人画像；
- Agent 的筛选经验、检索策略和工作方法进入经验记忆；
- 精读过程保留原始会话，完成后生成结构化总结。

### 11.2 行为

- Agent 可以自由新增和修改个人画像与经验记忆；
- 每次任务在需要时显式检索记忆；
- Agent 不得假定以前的记忆必然存在；
- Web 提供独立记忆页面，可查看、编辑、删除和停用记忆；
- 记忆显示来源、创建时间和最近更新时间。

## 12. Agent 提示词与模型

- 使用单一、已在 Codex 中配置好的 DeepSeek 兼容模型提供方；
- 系统不负责管理 Codex API 地址、模型、密钥或运行状态；
- 每日任务提示词使用稳定前缀：角色、筛选标准、图谱规则、工具说明和输出结构固定；
- 日期、候选论文、节点上下文和相关记忆放在动态后缀；
- 目标是在兼容 API 支持时提高提示词缓存命中率。

## 13. 页面与导航

首版顶部导航包含：

- 每日简报；
- 日报归档；
- 研究图谱；
- 论文库（含“论文库”和“积累库”两个页签）；
- 记忆；
- 任务与日志；
- 设置。

所有主要页面均可打开全局 Agent；论文详情额外提供专属精读对话。

- Web 默认使用亮色模式，并遵循 Material UI 的组件、主题、响应式断点和可访问性交互规范；
- 顶部导航使用带安全外边距的悬浮毛玻璃样式，在桌面端与移动端均不贴边；普通内容卡片采用 MUI Dashboard 模板的白色、细边框和无阴影样式；
- 桌面端顶部导航项与研究助手按钮使用正文字号，保证清晰可读；
- 页面文字使用面向最终用户的产品语言，不显示内部流程标语或开发术语；
- 桌面端所有 Agent 对话抽屉均可拖动调整宽度并记住用户设置；移动端使用全屏或页签式对话视图。

## 14. 任务、日志与备份

- Web 可查看任务状态、开始/结束时间和失败原因；
- 支持立即生成一期日报；
- 支持手动重跑失败任务；
- 失败后保留上一期可用日报；
- Agent 的数据操作写入简洁日志，不建设复杂回滚界面；
- 论文与 PDF 默认不由 Agent 删除；
- 每日将 Skill、配置、结构化论文元数据、分析、图谱、日报、记忆和日志导出提交到服务器本地 Git；
- PDF、会话和数据库文件不直接作为频繁变动内容提交 Git；
- 首版不推送远端备份仓库。

## 15. 非功能要求

- Web 在主流桌面浏览器和移动浏览器上可用；
- 所有前端触发的 LLM 交互均使用增量流式传输，避免等待完整回答后才呈现；
- API 返回的业务时间统一按北京时间（UTC+8）显示和序列化；
- 移动端 PDF 阅读是首版核心场景，不得仅做只读降级页面；
- 所有 Agent 写操作经 Toolkit CLI 和 Server 校验；
- CLI 命令应支持机器可读错误、幂等键和安全重试；
- API 密钥不得写入仓库、日志或 Web 响应；
- PDF 与用户阅读记录属于私有数据，不向未受信设备暴露；
- 论文分析需记录证据位置，无法可靠确认的信息明确标为未知，不臆测通讯作者或单位。

## 16. 首版验收标准

1. 能从 BibTeX 初始化相关论文和一张可浏览的研究问题图谱；
2. 能按大分类分页回溯 arXiv，领域及兴趣筛选到约 100 篇，再选出 20–50 篇日报并完成前 10 篇全文分析；
3. 能在配置的北京时间（默认 09:05）自动启动任务，并在成功时发布日报；
4. 任务失败能展示原因并由用户手动重跑；
5. 能提交 URL、arXiv ID/链接和 PDF，并正确去重；
6. 手机可完整阅读 PDF、翻译、高亮、记笔记和引用原文询问 Agent；
7. Agent 回答中的 PDF 引用可点击回到对应原文位置；
8. 研究节点中的论文均出现在论文库，用户能继续按精读状态、优质和标签筛选；
9. Agent 能通过 Toolkit CLI 新增和更新节点、边、进展、想法、兴趣画像与记忆；
10. Force Graph 能稳定显示局部子图并按需扩展，不持续乱跑；
11. 日报归档、精读论文库、记忆、任务日志和设置页面均可使用；
12. 结构化数据能够每日提交到服务器本地 Git；
13. 整个闭环无需应用账号登录，受信设备跨网络可访问。
